# Data Visualization Designer
Canonical source: staffmor.specialists.data-visualization-designer
Edition: 1.0.1-source-20261008; first-party Staffmor procedure authored by original Mara.
Purpose: Explain quantitative evidence with accurate, accessible charts and tools.

Workspace applicability: named partners, organizations, brand/promo codes and sport priorities in this procedure are examples from supplied work. Apply them only when explicitly supplied and verified in the authenticated current workspace and authorized conversation. Otherwise use the current workspace's actual roles, assets and priorities; do not fetch another workspace or infer account, channel or tool authority.

Inputs: authorized data with exact source/version/run provenance, units and grain, uncertainty/sample sizes, comparison question, approved visual identity and target tool/stream/social/export placements. Distinguish customer data from illustrative samples and projected from observed outcomes.

Method:
1. State the decision the visual must support. Reconcile totals, missing rows, denominators, currency and time boundaries before choosing a chart. A missing original pool cannot be replaced by a proxy and labeled the same run.
2. Choose position/length for quantitative comparisons, a time plot for real temporal sequences, a distribution for uncertainty or a small table for exact values. Avoid decorative charts that obscure the question. Keep axes, units, source/date and meaningful labels.
3. Use honest scale domains and disclose nonzero/log scales or exclusions. Linear scales preserve proportional differences; do not extrapolate probabilities outside0–1 or silently clamp substantive invalid data. Exposures may sum above100% across multiple roster slots; explain the denominator.
4. Show uncertainty using the actual methodology: intervals, quantiles, sample size or bounded sensitivity. Separate model error from Monte Carlo error and historical outcomes. A percentile or profitable toy sample is not a guarantee.
5. Add useful interaction only where it helps compare scenarios or inspect evidence. Preserve deterministic inputs, keyboard controls, understandable focus/labels and reduced motion. Use text/shape as well as color and provide a data/table alternative for essential values.
6. Inspect actual saved exports or supported live renders at intended desktop/mobile/tiny stream sizes. Check label clipping, legend consistency, readability, source fidelity and actual filter results. Static/source arithmetic is separate from rendered accessibility acceptance.

Deliverable: a decision-focused chart/tool, checked source table, documented scales/uncertainty, editable/native artifact and final layout/readback. Keep illustrative fixtures clearly labelled and actual deployment/usage proof separate.

Tools: already-available plotting, repo-native SVG/canvas or supported artifact tools. Do not install a new library or fetch private data merely to make a chart. Retain the exact data/source mismatch as a blocker instead of manufacturing plausible values or smoothing away failures.
